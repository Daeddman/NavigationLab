# Як пояснити лабораторні простими словами

## З чого почати

«Це один застосунок, який я поступово доповнював. У першій роботі зробив
екрани та кнопки. У другій додав переходи всередині лічильника.
У третій додав список авторів і книг. Код розділено за MVVM».

## Лабораторна №2

1. MainActivity лише отримує ViewModel, задає тему та запускає NavigationLabApp.
2. AppDestinations перелічує основні вкладки.
3. CounterNavigationGraph описує три адреси підекранів лічильника.
4. rememberNavController створює контролер переходів.
5. NavHost у CounterNavigationScreen показує підекран, що відповідає поточній адресі.
6. composable пов'язує адресу з Compose-функцією екрана.
7. navigate відкриває наступний підекран і додає його до стеку.
8. popBackStack прибирає верхній підекран: попередній знову стає видимим.
9. navigateUp використано для верхньої кнопки повернення.
10. launchSingleTop не створює ще одну копію адреси, яка вже на вершині стеку.

Стек — історія відкритих підекранів. Після переходів він містить лічильник,
статистику й довідку. «Назад» прибирає довідку, наступне «Назад» — статистику.
Системне повернення обробляє NavHost. Перемикання основних вкладок через when
саме по собі не є історією переходів між вкладками.

Екрани приймають callback-функції, наприклад onNavigateToHelp.
Кнопка викликає callback, а NavHost вирішує, куди перейти.
Так екрану не потрібно знати весь навігаційний контролер.

## Лабораторна №3

1. Author — дані автора; Book — дані книги та її автора.
2. LibraryItem — спільний тип для елементів одного змішаного списку.
3. AuthorRow — третій тип, який містить список авторів для горизонтальної добірки.
4. DemoLibraryRepository.getItems створює тестові об'єкти та повертає список.
5. LabViewModel отримує його під час створення та зберігає у LabState.
6. NavigationLabApp читає StateFlow через collectAsStateWithLifecycle.
7. MessageScreen отримує список параметром.
8. LazyColumn відображає його вертикально; items перебирає елементи.
9. when перевіряє тип: Author → AuthorCard, Book → BookCard, AuthorRow → AuthorRowCard.
10. AuthorRowCard використовує LazyRow для горизонтального прокручування.
11. weight(1f) займає висоту, яка залишилася після заголовків та кнопки.
12. key = item.id допомагає Compose розпізнавати той самий елемент; contentType розрізняє види карток.

## Що робить кожна функція LabViewModel

- selectDestination: змінює активну вкладку.
- incrementCounter: збільшує лічильник на 1.
- toggleMessage: перемикає булеве значення; екран за ним вибирає текст.
- addPoints: додає 5 балів.

_state — внутрішній MutableStateFlow, який можна оновлювати.
state — доступний UI потік лише для читання.
update бере попередній стан, а copy створює новий із потрібною зміною.
Інші поля залишаються попередніми. UI отримує оновлення та перемальовує залежні елементи.

ViewModel зберігає дані під час звичайного повороту Activity.
Це не база даних: після завершення процесу числа можуть початися з нуля.
remember зберігає значення між рекомпозиціями, rememberSaveable також може
відновлювати придатні до збереження значення після перестворення Activity.
У цій версії даними керує ViewModel; контролер і стан прокрутки належать UI.
