## Пункт 0: як працюють списки

LazyColumn — список з вертикальним прокручуванням.
LazyRow — список з горизонтальним прокручуванням.
Вони створюють елементи за потреби, зокрема видиму частину та елементи для
попередньої підготовки, замість одночасного компонування всього набору даних.

- items перебирає моделі та викликає потрібну Compose-функцію.
- key — стабільний унікальний ідентифікатор елемента в цьому списку.
- contentType відокремлює різні види розмітки для повторного використання композицій.
- weight(1f) у Column віддає списку решту доступної висоти.

Джерело: https://developer.android.com/develop/ui/compose/lists

## Розподіл коду

- MainActivity.kt — запускає UI і отримує ViewModel.
- model/LibraryItem.kt — спільний тип елемента списку.
- model/Author.kt, Book.kt — моделі автора та книги.
- model/AuthorRow.kt — модель горизонтальної добірки.
- model/LabState.kt — стан вкладки, чисел, повідомлення і списку.
- repository/LibraryRepository.kt — опис джерела даних.
- repository/DemoLibraryRepository.kt — створення тестових даних.
- viewmodel/LabViewModel.kt — отримання списку один раз при створенні, обробка дій користувача, StateFlow.
- ui/NavigationLabApp.kt — читає стан через collectAsStateWithLifecycle і передає його екранам.
- ui/screens/MessageScreen.kt — заголовки, змішаний LazyColumn, кнопка.
- ui/components/ — картки двох моделей і горизонтальна добірка.
- navigation/ та CounterNavigationScreen.kt — маршрути й переходи лабораторної №2.

UI отримує дані та callback-функції. Репозиторій не знає про Compose,
ViewModel не зберігає NavController, екран не створює тестові дані.
MutableStateFlow — внутрішній механізм ViewModel, а назовні відкрито StateFlow лише для читання.
MVVM не забороняє змінний стан: він визначає, хто ним керує.

Дані зберігаються в пам'яті ViewModel і переживають звичайний поворот Activity.
Постійного зберігання після завершення процесу тут немає.
Список незмінний з боку інтерфейсу; база даних та мережа для цієї роботи не потрібні.

## Запуск

1. Завантажити ZIP гілки lab3-lists або клонувати її.
2. Розпакувати й відкрити в Android Studio корінь з settings.gradle.kts.
3. Дочекатися Gradle Sync. Потрібні SDK 37 і Gradle JDK 25.
4. Вибрати емулятор/телефон з Android 9 (API 28) або новішим та натиснути Run.
5. Для №2 відкрити «Лічильник», для №3 — «Повідомлення».

Збережені версії початкового проєкту: AGP 9.5.1, Gradle 9.6.0,
compileSdk/targetSdk 37. Lifecycle 2.10.0, Navigation Compose 2.9.6.
